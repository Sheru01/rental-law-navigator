Change tracking

A diff between two dates, not a second product

Presentation only. The underlying generic diff primitive is Codex's.
No test answer is encoded here.
THE CONTROL
as of [date A]
as of [date B]
One parameter moves. Every card re-renders. There is no separate change-tracking screen to navigate to, because there is no separate engine.
+ Rule added
Present at the later date, absent at the earlier one. The card slides in with a left rule and a one-line reason.
[rule_id]
+ now in the result set
− Rule removed
Dropped out between the dates. Rendered struck through and dimmed, but still present, so a disappearance is never silent.
[rule_id]
Status changed
Same rule, different result. The most common and most persuasive diff. Old value struck, new value bold, on one line.
[prior state] → [new state]
Effective date changed
The date itself moved, usually because a better source was found. The provenance tag moves with it, so a date that went from inferred to stated shows that upgrade.
eff [old] → eff [new]
Coverage changed
The rule still applies, but to a different set of buildings. Shown as a count delta plus the predicate that moved.
[n] → [n] addresses
predicate: [what changed]
Evidence insufficient
The diff itself could not be computed, because one side rests on a source we do not hold. This is the rung that must never render as an empty set.
"No change" and "could not determine" are different findings and are drawn differently. An empty result always states which of the two it is.
PER-TEST SUMMARY BLOCK, ONE PER CHANGE CASE
[test_id] · [test title] [type]
AFFECTED
[n]
CONFLICT FLAGGED
[n]
INDETERMINATE
[n]
Notes. Written as prose for a human reader, not a debug string. States what the system concluded, what it could not determine and why, and which source documents back it. This field is judged, so it is designed, not dumped.
An affected count of zero is displayed with its reason attached: either the change genuinely reaches no address in the sample, or the evidence to decide was missing. Those two zeros look different on screen and read differently out loud.
INTEGRATION REQUIREMENTS, UNRESOLVED
This board is drawn against an interface that is not frozen. Three things must be reconciled once Codex commits, and each is a presentation dependency, not a request to change his design.
A1The six diff kinds above are my taxonomy. If the primitive emits a different or smaller set, the cards collapse to match it rather than inventing categories it does not produce.
A2"Evidence insufficient" needs to be distinguishable from an empty affected set in the data. If both arrive as an empty list, the UI cannot tell them apart and the most important distinction on this board is lost.
A3Per-address prior and current state is needed to draw a status change. A test-level affected list alone supports the counts but not the struck-through line.
None of these blocks the demo. Without them the cards degrade to counts and notes, which is still a complete story.
