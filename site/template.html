01

Extract, then decide

A model turns source legal text into structured rules: plain-language requirement on top, machine-readable coverage test underneath. From there on, deterministic code evaluates every address. A language model never decides whether a rule applies to a building.

02

Unknown, at full weight

When the public record lacks the one fact a rule turns on, the answer is unknown and it says which fact. Same size card, same provenance chain, no greyed-out apology. Specific uncertainty reads as rigor. Vague uncertainty reads as failure.

03

Every claim to the exact text

Each rule carries a quoted span that is located by exact match inside the source document at render time. If the sentence is not there, the rule does not ship. Two readers extracted blind; their disagreements were published, not reconciled quietly.

    The by-product worth keeping

    Evidence Debt

    The unknowns are not what the system failed to answer. They are a sourced map of where the public record cannot support an answer at all.

    An unanswerable question is a finding about the record, not a failure of the reader.

    Evidence Debt Ledger

    Counts are a client-side grouping of the engine's own unknown and indeterminate results over the evaluated address set. Nothing is computed separately, estimated, or extrapolated past that set.

    What this does not claim

    • Not that the data is wrong. The published record does not contain the field, which is a different and narrower claim.
    • Not a generalisation past the sample. The ledger describes this evaluated set on one retrieval date.
    • Not that any jurisdiction is negligent. Assessor schemas differ for ordinary historical reasons.
